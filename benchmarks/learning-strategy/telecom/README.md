## What has been qualified

In [qualification-v1.json](qualification-v1.json), all 41 reference repairs succeed. All 41 no-op executions fail, and all 41 executions omitting the first required repair fail. Strict replay reproduces each final native state. An additional guard checks unrelated accounts, lines, bills, plan definitions and server device records; 41 deliberate account corruptions are detected. This guard supplements native assertions, which do not promise comprehensive noninterference. It is not a complete conversational policy-compliance evaluator.

The native process exposes reset, permitted role-specific tool calls, and final judgment to the experiment host. Models receive only their own tools and context. Task IDs, initialization actions, reference solutions, grading criteria and the qualification report never enter model prompts. The customer's private scenario and device tool responses remain in the customer's conversation. Actor and customer communicate through speech and explicitly selected structured public observations. Neither model receives intermediate grades. Only the host can reset or judge an episode.

The actor can reason normally and make native tool calls. The simulated customer operates its own tools when asked, reports observed outcomes, and ends the conversation. Both roles use the same pinned model. Text accompanying a tool call stays private until that participant yields a speech-only reply. The user may include final speech with its terminal tool call. This adaptation is explicit and is covered by replay auditing.

## Running the pilot

The corrected collector is `rediscovery2-study.mjs prepare <new-id> <seed|discovery|confirmation|fresh> [source-id]`, followed by `run <new-id>`, under `node --import tsx`. It amends the simulated customer's exact purchase preference, separates static and conditional program contracts, preserves complete selected actor-visible traces and allows one mechanical compiler-feedback revision per proposal. It uses the existing private strategy archive and resource stores. This is an explicit benchmark variant; native tools and outcome assertions are unchanged.

After each completed corrected stage, run `rediscovery2-audit.mjs <run-directory>` with plain `node`, saving successful stdout as `audit.json`, then run `rediscovery2-analyze.mjs`, saving `analysis.json`. Analysis exclusively creates `trial-data.jsonl`. Source stages also require a separate measurement review before advancement. Confirmation freezes all four selected candidates; fresh evaluation requires its predefined gate. Do not modify frozen sources, rerun a collector or exporter over existing artifacts, or reuse consumed cases as globally fresh evaluation. See the [corrected study report](../../../docs/memory/telecom-corrected-autonomous-learning.md) for review artifacts and interpretation.

`diagnostic-actions.mjs` is an offline follow-up candidate for role-qualified native probe actions. It passed four self-contained tests and caught all five wrong-role plans among 17 recorded diagnostic plans. The corrected paid collector does not import it, and these checks establish no model or task benefit.

`diagnostic-session.mjs` adds a separately bounded interactive diagnostic sandbox: exact parent replay, one selector decision after each complete tool result, role validation, evidence preservation and no implicit retry after transport failure. Nine focused tests passed, including rejection of success credit when unrelated account state changes. `diagnostic-session-qualify.mjs <audited-discovery-root> <new-output-directory>` runs scripted native integration checks on two consumed parent states; the retained qualification repaired 2/2, produced failures for all three omission controls and preserved 2/2 already-repaired states. It makes no model calls, and the frozen paid study does not use this component. A provider-backed selector and a new frozen comparison are still needed to measure learning benefit.

The pilot freezes four development cases before paid collection: task indices 0, 14, 21 and 45. They cover a two-repair mobile-data problem, a seven-repair mobile-data problem, a seven-repair service problem and a nine-repair MMS problem. This deliberate sample is for headroom qualification, not population accuracy. Each episode permits 96 model calls and $1.25, subject to the stricter remaining project ceiling. Actor and customer calls both count.

Learning is warranted only if this pilot has both a success and a failure, completes naturally without interface/resource truncation, and inspection attributes the failure to the actor. If every case succeeds, preserve the adapter and move to a harder prospectively defined panel; do not manufacture a learning result by evolving on already-solved tasks. Pilot cases remain development-only. A subsequent learning comparison must freeze its own held-out cases and distinguish verified procedure reuse from proposer evolution.

The current collector treats successful human handoff as terminal. Its source gate still requires successful repairs; handing off an unresolved supported task is not a success. Earlier frozen runs waited for user termination, and their extra costs remain charged.

Passing a failed correction as the final argument enables one append-only experiment. It reuses the two source cases, includes ordered actor-visible dialogue from the pilot and previous correction, and asks for at most 600 additional characters. The lab preserves the original actor text and fixed proposer. Feedback is bounded to 32000 characters per source case and rejected on overflow. The redaction projection is specific to these fictional source customers; it is not a privacy filter for arbitrary real users. Source qualification still requires 2/2 repairs before the same two reserved recipient cases run.

The additive experiment enables five-minute automatic conversation caching for both actors and simulated customers, alongside the existing policy cache, using the [documented Messages API option](https://platform.claude.com/docs/en/build-with-claude/prompt-caching). Prompt content, model and conservative request reservations stay unchanged. Cache hits and writes are charged from actual usage receipts. Cost comparisons with earlier collections must account for this collector change and the terminal handoff repair; they do not isolate a learning efficiency effect.

The audit recreates each run's frozen source tree and replays recorded model responses through fresh native environments without paid calls. It reconstructs exact requests, compares final judgments, verifies source/prompt hashes, and reconciles usage with episode totals and the existing SQLite ledger. It reports working-tree changes separately, so fixes do not invalidate historical evidence. Python dependency versions and native qualification evidence are included in each run's freeze. Post-handoff prefix diagnostics are explicitly post-collection and never feed candidate selection.

For a learning run, save a successful audit's JSON stdout as `audit.json` before using `analyze.mjs`. The analyzer reports recipient accuracy, model/tool calls, actual provider spending, and a counterfactual price with every observed input token charged at the same base rate. This prevents warm-cache savings from being mistaken for more efficient problem solving. Its comparison is descriptive and does not establish statistical significance. Reserved cases 38 and 41 have now been observed in evaluation and cannot be reused as a fresh final test after tuning.
